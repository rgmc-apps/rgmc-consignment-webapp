## Context & Gotchas

### `ApiError.body` is only set for requests with a body
- `POST /bc/sales-orders` and `POST /bc/custom/sales-return-orders` both send JSON bodies → `body` will be populated on error
- `GET` endpoints (fetching brands, customers, items, etc.) have no body → `body` will be `undefined` → `payload=` will not appear in the report URL for those errors
- This is intentional and correct behavior

### Payload is spread, not nested
The payload object is `{ screen, ...resolvedPayload }` — the request body fields are spread at the top level, not wrapped in a sub-key. So a sales order error produces `{ "screen": "/submit", "customerNo": "C001", "lines": [...] }`, not `{ "screen": "/submit", "body": { ... } }`. If the request body is not a plain object (e.g., it's a string or number), it's wrapped as `{ screen, data: value }`.

### Report URL base
`VITE_GATEWAY_URL` env var → fallback `https://rgmc-gateway-935246372408.asia-southeast1.run.app` → appended with `/report-issue`.

Previous handoff noted the URL had a region typo (`asiasoutheast1` vs `asia-southeast1`). That was fixed in a prior session. The fallback in `useErrorReporter.ts` line 4 now uses the correct hyphenated region.
